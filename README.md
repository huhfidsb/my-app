# 家計簿アプリ（MoneyPilot）

Express + PostgreSQL（生SQL） + EJS で動く、家計簿・割り勘・分析・カレンダーのアプリです。
ユーザー登録制になっており、各ユーザーの記録は他のユーザーから見えません。

## 起動手順

```bash
npm install
npm start
```

サーバー起動時に `sql/schema.sql` を自動実行し、必要なテーブルがなければ作成・アップグレードします
（`CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ... IF NOT EXISTS` のみなので、既存データがあっても壊しません）。
`.env` の `DATABASE_URL` が指す PostgreSQL に接続できる状態で起動してください。

`.env` には `SESSION_SECRET`（ログインセッションの署名用ランダム文字列）も必要です。
開発用にランダム生成した値を入れていますが、本番環境では別の値に差し替えることをおすすめします。

### メール送信（新規登録・パスワード再設定の認証コード用）

`.env` に `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` 等を設定すると、nodemailer 経由で実際に
メールを送信します。**未設定の場合は、認証コードがサーバーのコンソールに出力されるだけの
開発用フォールバックになります**（ローカルでの動作確認に便利です）。

```
SMTP_HOST="smtp.example.com"
SMTP_PORT="587"
SMTP_USER="noreply.moneypilot@gmail.com"
SMTP_PASS="<ここには実パスワードを入れ、Gitにはコミットしない>"
MAIL_FROM="MoneyPilot <no-reply@example.com>"
```

`SMTP_PASS` のような秘密情報は、`.env` やデプロイ先の secret/環境変数にだけ置いてください。コードや README には残さない運用にしておくと、安全に管理できます。

## 画面レイアウトについて

配置（縦1カラムの並び順）はスマホでもPCでも常に同じにしたまま、画面の横幅に合わせて
ページ全体を拡大縮小して表示します（`views/index.ejs` の `#scaleRoot` に対する
`transform: scale()`）。画面が広いほど全体が大きく表示され、その分ページ全体が縦に
スクロールする形になります（内部の枠だけがスクロールすることはありません）。

- 基準デザイン幅は560pxです（`BASE_WIDTH` 定数）。
- 極端に大きな画面で文字が巨大化しすぎないよう、拡大率の上限を1.85倍にしています
  （`MAX_SCALE` 定数）。上限をなくしたい・変えたい場合はこの値を調整してください。
- 小さすぎる画面でも見づらくならないよう、縮小率の下限を0.6倍にしています（`MIN_SCALE`）。

## ユーザー登録・ログインについて

- 新規登録は「メールアドレス入力 → 6桁の認証コードをメールで受け取り確認 → ユーザー名・
  パスワードを設定」の3ステップです。以後は、設定したユーザー名とパスワードでログインします。
- パスワードを忘れた場合は、ログイン画面の「パスワードをお忘れですか？」から、登録済みの
  メールアドレスに認証コードを送って再設定できます（このときユーザー名もあわせて画面に表示します）。
- PINコードによるログインは廃止しました。

### Face ID・指紋（生体認証）ログイン

- ⚠️ この開発環境ではネットワークが使えず、FIDO2の署名検証ライブラリ
  （`@simplewebauthn/server` など）を追加インストールできませんでした。そのため、
  「端末に保存した高強度ランダムトークン（httpOnly cookie）を、ブラウザのWebAuthn生体認証
  プロンプトでゲートする」という実用的な簡易実装にしています。
  - 端末側の突破口（cookieの値）を持っていない限りログインはできないため、実用上の安全性は
    確保しつつ、Face ID・指紋・画面ロック等でサッと再ログインできる体験を実現しています。
  - より厳密なFIDO2準拠（署名の暗号検証）にしたい場合は、ネットワークが使える環境で
    `npm install @simplewebauthn/server` を行い、`/api/auth/webauthn/*` の実装を
    差し替えることをおすすめします。
- 設定画面（左上のハンバーガーメニュー）から、端末の登録・削除ができます。

## 設定画面（ハンバーガーメニュー）

画面左上の三本線アイコンから開きます。

- アカウント情報の確認・ログアウト
- 貯蓄目標額の設定（空欄でOK）
- 生体認証端末の登録・削除

「分析」タブの表示・非表示切り替えは廃止し、常に表示するようにしました。

## この環境での制約について

この開発サンドボックスはネットワークアクセスがなく、`npm install` で新しいパッケージ
（`nodemailer` を含む）を追加したり、実際のPostgreSQLやSMTPサーバーに接続して動作確認
したりすることができませんでした。そのため：

- DBアクセスは Prisma Client を経由せず、`pg` パッケージで直接SQLを発行する構成にしています
  （`lib/db.ts`）。`prisma/schema.prisma` は参照用として残しています。
- コードの構文チェック・EJSテンプレートのレンダリングチェックは行いましたが、実際の
  PostgreSQL・SMTPサーバーに接続しての動作確認はできていません。**デプロイ前に、ご自身の
  環境（ネットワークがつながる場所）で一度動作確認をお願いします。**
  Claude Code などネットワークが使える環境で `npm install && npm start` すると、
  起動時に自動でテーブルが作成・アップグレードされます。

## 主な機能

- ユーザーごとの家計簿（メール認証つき登録・ログイン・パスワード再設定・生体認証）
- 支出・収入の記録と一覧表示
- 満足度と投資・消費・浪費の分類保存
- 月次収支グラフの自動生成（全幅表示）
- 月次分析と円グラフ表示（常時表示・全幅表示）
- 割り勘の精算計算と保存
- 日別カレンダー表示（全幅表示）
- 画面サイズに応じて配置そのままに拡大縮小するレイアウト
- 設定画面（貯蓄目標額、生体認証端末管理）

## 追加の変更

- **カテゴリーを支出・収入で別リストに分離**しました（`categories`テーブルに`kind`列を追加）。
  デフォルトカテゴリーも支出用（食費・生活費・交通費・趣味）と収入用（給与・副業・お小遣い・
  その他収入）に分かれています。支出⇄収入をワンタッチ切り替えすると、カテゴリー選択肢も
  連動して切り替わります。
- **月次収支グラフの吹き出し位置のズレを修正**しました。キャンバス自身の余白（padding）分の
  オフセットを考慮していなかったのが原因でした。
- **ログインをメールアドレス＋パスワード方式に変更**しました（ユーザー名はログインに使いません。
  新規登録時に設定したユーザー名は表示用として残ります）。同じメールアドレスでの重複登録は
  一意制約と登録時チェックの両方で防止しています。
- 各タブの説明書き（`.hint`）を削除しました。ホーム画面の紹介文（2文）のみ残しています。
- 画面の拡大縮小の基準幅を560px→420px（スマホサイズに近い基準）に変更し、拡大率の上限も
  1.85倍→1.3倍に引き下げました。PCなど横幅が広い画面では、スマホに近いサイズのまま中央表示され、
  左右に余白ができます。
- 中央寄せの実装を `margin: auto` から `translateX` を使った計算方式に変更し、画面サイズに
  かかわらず中央からずれない・見切れないようにしました（スマホで右にずれて見える不具合の修正）。
- 月選択の「＜〇月＞」ナビを横に広く・文字を大きくしました。
- カレンダーの日ごとの金額表示が枠からはみ出さないよう、
  - 基本の文字サイズを小さめにし、
  - それでも収まらない場合はJavaScriptで自動的にさらに文字を縮小する仕組みを追加しました（`fitCalendarAmounts`関数）。
  - あわせて、金額が0円の日は表示を省略し、見た目をすっきりさせました。
- **収入カテゴリーの追加編集ができないバグを修正**しました。原因は、既存アカウントのカテゴリーが
  すべて支出用として保存されていた（カテゴリー分離の移行時にすべて`EXPENSE`扱いになっていた）ため、
  収入側のカテゴリーが0件になり、プルダウンの選択肢が「（追加・編集）」だけになって
  `change`イベントが発火しなくなっていたことでした。
  - 起動時（ダッシュボード読み込み時）に、支出・収入どちらかのカテゴリーが0件のアカウントには
    自動でデフォルトカテゴリーを補充するようにしました（`ensureDefaultCategoriesAndPaymentMethods`）。
  - あわせて、選択肢が0件のときは自動的に管理パネルを開く安全策も追加し、同様の不具合が
    今後起きないようにしました。
  - デフォルトで「給与」を含む収入カテゴリー（給与・副業・お小遣い・その他収入）を用意しています。
- **満足度・投資消費浪費の項目を全て削除**しました（フォーム・一覧表示・分析・DBカラムすべて）。
- **支払い方法を、カテゴリーと同じ仕組みのユーザー編集可能なリストに変更**しました。
  デフォルトは「現金・カード・QRコード・銀行振込・その他」で、追加・編集・削除ができます。
- ホーム画面の「three-layer finance dashboard」表記と、支出・収入トグル上部の「区分」ラベルを削除しました。
- **月次収支グラフの吹き出し位置のズレを根本原因から修正**しました。前回の修正では
  キャンバス要素自身の余白オフセットしか考慮しておらず、画面サイズに合わせた拡大縮小
  （ページ全体の`transform: scale()`）の影響で、グラフの描画に使う座標とマウス位置の座標の
  基準がズレていたのが本当の原因でした。キャンバスのサイズ計算を`getBoundingClientRect()`
  （拡大縮小の影響を受ける）から`offsetWidth`/`offsetHeight`（影響を受けない）に変更し、
  マウス位置の取得も`event.offsetX`/`offsetY`を使う方式に変更することで解消しています。
- **「使い方ガイド」オン/オフ機能を追加**しました（設定パネル）。オフにすると画面内の説明文
  （`.guide-text`クラスが付いた要素）をすべて非表示にします。
- **サブスク機能を追加**：記録タブの保存ボタンと同じ行、右端に「サブスクはこちら」ボタンを設置。
  押すと記録一覧の場所がサブスク一覧に切り替わり、追加・編集・削除ができます
  （`subscriptions`テーブル新規、`/api/subscriptions` API）。
- **月予算設定を追加**：貯蓄管理タブに、支出カテゴリーごとの月間予算を設定できる欄を追加しました。
  予算を設定したカテゴリー／月のみ表示されます（`budgets`テーブル新規、`/api/budgets` API）。
  - 分析タブに反映：先月に予算を設定していた場合のみ「先月は◯円貯蓄できました！」／
    「◯円足りませんでした」を表示。今月に予算を設定していた場合のみ、残り日数とカテゴリーごとの
    残り予算を表示します。
- **ハンバーガーメニューからユーザー名の変更、退会（アカウント削除）ができるようにしました。**
  退会は「データが削除され元に戻せない」という警告 →最終確認、の2段階確認を経てから実行します。
- 設定パネルから「貯蓄の目標額」欄を削除しました（貯蓄管理タブの入力と重複するため）。
- 月選択の「＜◯月＞」の横幅を、他の要素と同じ（パネル全幅）に統一しました。
- 分析タブの「選択中の月の収支」を、収入－支出＝収支の関係が視覚的にわかるレイアウトに変更し、
  平均日次支出も同じ場所にまとめました。
- 記録一覧・カレンダーの日別記録・円グラフの凡例（カテゴリー内訳）の文字サイズと縦の余白を
  小さくしました（横幅は変更していません）。
- 金額欄のプレースホルダーを「1200」→「0」に変更。
- 収支記録の日付欄は、開いた時点の今日の日付がデフォルトで入るようにしました。
- **月次収支の棒グラフをホーム画面（アプリを開いた直後の一番上）に移動**し、今月の収支の数値
  カードは削除しました。年は常に「アプリを開いた日を含む年（1月〜12月）」を表示します
  （分析タブの月選択とは連動しません）。
- スマホでハンバーガーメニューを開いてスクロールする際、背後の画面が一緒に動いてしまう問題を
  修正しました（メニューを開いている間は背景のスクロールをロックする方式）。また、メニュー内の
  一番下の項目が隠れないよう、下側に余白を追加しました。
- 割り勘タブの「対象者」チェックボックスと名前のズレを修正しました
  （チェックボックスの余白リセット、テキストの余分な空白除去）。
